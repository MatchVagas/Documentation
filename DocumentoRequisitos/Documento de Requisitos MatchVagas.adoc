== Introdução

=== Propósito
Este documento tem como objetivo especificar de forma clara, completa e verificável os requisitos do Sistema de Banco de Vagas de Trabalho e Estágio, servindo como referência para clientes, desenvolvedores, testadores e demais partes interessadas.

=== Especificação de Requisitos de Software
O documento de requisitos descreve os requisitos funcionais e não funcionais que o sistema deve atender. Ele apresenta os seguintes tópicos listados abaixo:

* Descrição geral do sistema: apresenta uma visão geral do sistema, caracterizando qual é o seu escopo e descrevendo seus usuários.
* Requisitos funcionais: especificam todos os requisitos funcionais do sistema, descrevendo os fluxos de eventos, prioridades, atores, entradas e saídas de cada caso de uso a ser implementado.

=== Escopo do Sistema
O sistema permitirá o cadastro, divulgação e gerenciamento de vagas de trabalho e estágio, bem como o cadastro de candidatos e empresas, possibilitando candidaturas e acompanhamento do processo.

Principais benefícios:

* Seu primeiro emprego ou estágio começa aqui.
* Centralização das oportunidades de trabalho e estágio.
* Facilitação do processo de candidatura.
* Apoio ao recrutamento por parte das empresas.

== Requisitos

=== Identificação dos Requisitos
Os requisitos do sistema, por convenção, serão referenciados por meio da subseção onde eles estão descritos, seguido do identificador do requisito, de acordo com a especificação a seguir:

[nome da subseção, identificador do requisito].

Os requisitos devem ser identificados com um identificador único. A numeração inicia com o identificador [RF001] ou [RNF001] e prossegue sendo incrementada à medida que forem surgindo novos requisitos.

=== Prioridades dos Requisitos
Para estabelecer a prioridade dos requisitos foram adotadas as seguintes denominações, "Essencial", "Importante" e "Desejável":

* *Essencial*: é o requisito sem o qual o sistema não entra em funcionamento. Requisitos essenciais são requisitos imprescindíveis.
* *Importante*: é o requisito sem o qual o sistema entra em funcionamento, mas de forma não satisfatória. Requisitos importantes devem ser implementados, porém, se não forem, o sistema poderá ser implementado e utilizado mesmo assim.
* *Desejável*: é o requisito que não compromete as funcionalidades básicas do sistema, isto é, o sistema pode funcionar de forma satisfatória sem ele. Requisitos desejáveis são requisitos que podem ser deixados para versões posteriores do sistema, caso não haja tempo hábil para implementá-los na versão que está sendo especificada.

== Descrição Geral do Sistema

=== Perspectiva do Produto
O sistema será uma aplicação web independente, acessível via navegadores modernos, utilizando arquitetura cliente-servidor e banco de dados relacional.

=== Funções do Produto
* Cadastro e autenticação de usuário.
* Gerenciamento de perfis de candidatos e empresas.
* Cadastro e manutenção de vagas.
* Busca e filtragem de oportunidades.
* Candidatura e acompanhamento de vagas.
* Administração do sistema.

=== Descrição dos Usuários

* *Candidato*: usuários que buscam vagas e se candidatam.
* *Empresa/Recrutador*: usuários que publicam e gerenciam vagas.
* *Administrador*: usuários com permissões de gestão global.

== Requisitos

=== Requisitos Funcionais
Requisitos funcionais descrevem as diversas funções que usuários e clientes querem ou precisam que o software ofereça, ou seja, são requisitos ligados diretamente à funcionalidade do software, que o sistema deve prover. Ian Sommerville define requisitos funcionais como: "São declarações dos serviços que o sistema deve fornecer, do modo como o sistema deve reagir a determinadas entradas e de como deve se comportar em determinadas situações."

==== [RF001] - Cadastro de Usuários
*Descrição*: Nesta parte o candidato deve adicionar seus dados para cadastro no banco de vagas. O Representante ou Recrutador adiciona dados da empresa para cadastro no banco sendo direcionado para uma área específica conforme o tipo de usuário (candidato ou empresa).

*Atores*: Candidato e Empresa

*Prioridade*: Essencial

*Entradas e pré-condições*: Nome, e-mail, senha, tipo de usuário, idade, data de nascimento, CPF, CNPJ (candidato ou empresa). Usuário não estar previamente cadastrado.

*Saída e pós-condição*: Conta de usuário criada no sistema. Usuário apto a realizar autenticação.

==== [RF002] - Autenticação
*Descrição*: O sistema deve permitir que usuários cadastrados realizem autenticação para acessar as funcionalidades conforme seu perfil.

*Atores*: Candidato, Empresa e Administrador

*Prioridade*: Essencial

*Entradas e pré-condições*: E-mail e senha. Usuário previamente cadastrado e ativo.

*Saída e pós-condição*: Sessão autenticada iniciada. Usuário com acesso às funcionalidades conforme seu perfil.

==== [RF003] - Gerenciamento de Perfil do Candidato
*Descrição*: O sistema deve permitir que candidatos autenticados gerenciem seu perfil, incluindo dados pessoais, formação acadêmica, experiências profissionais e currículo.

*Atores*: Candidato

*Prioridade*: Essencial

*Entradas e pré-condições*: Dados pessoais, formação acadêmica, experiências profissionais e currículo. Usuário autenticado como candidato.

*Saída e pós-condição*: Perfil do candidato atualizado. Dados disponíveis para candidatura a vagas.

==== [RF004] - Gerenciamento de Perfil da Empresa
*Descrição*: O sistema deve permitir que representantes de empresas ou recrutadores autenticados gerenciem o perfil da empresa.

*Atores*: Empresa/Recrutador

*Prioridade*: Essencial

*Entradas e pré-condições*: Razão Social da empresa, descrição, porte, ramo de atuação, site, endereço e informações de contato. Usuário autenticado como empresa.

*Saída e pós-condição*: Perfil da empresa atualizado. Empresa apta a cadastrar e gerenciar vagas.

==== [RF005] - Cadastro de Vagas
*Descrição*: O sistema deve permitir que empresas autenticadas cadastrem novas vagas de trabalho ou estágio.

*Atores*: Empresa/Recrutador

*Prioridade*: Essencial

*Entradas e pré-condições*: Título da vaga, descrição, requisitos, tipo (trabalho ou estágio), localidade e data de expiração. Empresa autenticada com perfil completo.

*Saída e pós-condição*: Vaga registrada no sistema. Vaga disponível para busca e candidatura.

==== [RF006] - Manutenção de Vagas
*Descrição*: O sistema deve permitir que empresas autenticadas realizem manutenção das vagas publicadas, incluindo edição, desativação ou remoção.

*Atores*: Empresa/Recrutador

*Prioridade*: Essencial

*Entradas e pré-condições*: Dados atualizados da vaga ou solicitação de exclusão. Empresa autenticada e proprietária da vaga.

*Saída e pós-condição*: Vaga atualizada, desativada ou removida. Informações refletidas imediatamente nas buscas.

==== [RF007] - Busca e Filtragem de Vagas
*Descrição*: Esta parte busca filtrar as vagas conforme as exigências das vagas e o perfil do candidato. O sistema deve recomendar vagas com compatibilidade ao perfil do usuário.

*Atores*: Candidato

*Prioridade*: Essencial

*Entradas e pré-condições*: Palavras-chave, área, localidade, tipo de vaga, idade e outros filtros pertinentes. Existência de vagas ativas no sistema.

*Saída e pós-condição*: Lista de vagas compatíveis com os critérios informados. Usuário visualiza oportunidades filtradas.

==== [RF008] - Candidatura à Vaga
*Descrição*: O candidato se candidata às vagas de interesse com o currículo já cadastrado no sistema, podendo acessar as vagas existentes. Caso não esteja cadastrado, é direcionado para o cadastro no banco de vagas.

*Atores*: Candidato

*Prioridade*: Essencial

*Entradas e pré-condições*: Identificador da vaga e currículo do candidato. Candidato autenticado e não previamente candidato à vaga.

*Saída e pós-condição*: Candidatura associada ao candidato e à vaga. Confirmação de candidatura registrada.

==== [RF009] - Acompanhamento de Candidaturas
*Descrição*: O candidato acompanha a situação atual da sua candidatura às vagas, sendo informado sobre cada passo do processo seletivo, incluindo notificações sobre mudanças de status.

*Atores*: Candidato

*Prioridade*: Essencial

*Entradas e pré-condições*: Solicitação de consulta de candidaturas. Candidato autenticado.

*Saída e pós-condição*: Lista de candidaturas com seus respectivos status. Candidato informado sobre o andamento do processo.

==== [RF010] - Administração do Sistema
*Descrição*: O sistema deve fornecer funcionalidades administrativas para gestão global de usuários, vagas e conteúdos.

*Atores*: Administrador

*Prioridade*: Essencial

*Entradas e pré-condições*: Comandos de gerenciamento (usuários, vagas e conteúdos). Usuário autenticado como administrador.

*Saída e pós-condição*: Alterações administrativas realizadas. Sistema atualizado conforme ações administrativas.

=== Requisitos Não Funcionais

==== [RNF001] - Disponibilidade
*Descrição*: O sistema deve estar disponível em, no mínimo, 99,5% do tempo durante o horário comercial (08h às 20h), com tolerância a janelas de manutenção previamente agendadas.

*Prioridade*: Importante

==== [RNF002] - Tempo de Resposta
*Descrição*: As operações de busca, filtragem e candidatura a vagas devem ter tempo de resposta inferior a 3 segundos em condições normais de uso.

*Prioridade*: Importante

==== [RNF003] - Segurança - Autenticação
*Descrição*: As senhas dos usuários devem ser armazenadas utilizando hash seguro (ex: bcrypt). O sistema deve utilizar HTTPS em todas as comunicações.

*Prioridade*: Essencial

==== [RNF004] - Privacidade e Proteção de Dados
*Descrição*: O sistema deve estar em conformidade com a LGPD, garantindo que o consentimento do usuário seja coletado e que os dados pessoais sejam tratados com segurança e transparência.

*Prioridade*: Essencial

==== [RNF005] - Acessibilidade
*Descrição*: O sistema deve atender às diretrizes de acessibilidade WCAG 2.1, nível AA, garantindo navegação por teclado, contraste adequado e compatibilidade com leitores de tela.

*Prioridade*: Importante

==== [RNF006] - Compatibilidade
*Descrição*: O sistema deve ser compatível com os navegadores mais recentes das principais plataformas (Chrome, Firefox, Edge e Safari), tanto em desktop quanto em dispositivos móveis.

*Prioridade*: Importante

==== [RNF007] - Integridade de Dados
*Descrição*: O sistema deve garantir a consistência dos dados armazenados em banco de dados relacional, utilizando transações ACID em operações críticas (ex: cadastro e candidatura).

*Prioridade*: Essencial

==== [RNF008] - Manutenibilidade
*Descrição*: O código-fonte deve seguir padrões de organização e documentação que permitam fácil manutenção e evolução. Deve-se utilizar versionamento com Git e adotar boas práticas como Clean Code.

*Prioridade*: Importante

==== [RNF009] - Usabilidade
*Descrição*: A interface do sistema deve ser intuitiva, com design responsivo e fluxos claros para os diferentes perfis de usuário (candidato, empresa e administrador).

*Prioridade*: Importante

==== [RNF010] - Confiabilidade
*Descrição*: O sistema não deve permitir candidaturas duplicadas para a mesma vaga e deve validar corretamente os dados inseridos nos formulários antes do envio. Garantido que o candidato não passe por tumultos.

*Prioridade*: Essencial
